# 新机器部署

> 仓库里只有代码和脚本，**有 7 样东西不在仓库里、必须在新机器上补**。
> 缺第 1~3 项会直接跑不起来；缺 4~7 项是能力降级。

## 一张表看清

| # | 依赖 | 缺了会怎样 | 怎么补 |
|---|---|---|---|
| 1 | **Node.js ≥ 20.11** | 跑不起来（用了 `import.meta.dirname`） | 装 Node 24，`node -v` 确认 |
| 2 | **DSH 本体** | 生成必失败（`bash` 里 spawn 不到） | `npm i -g @deepseek-ai/dsh`；路径怪就设 `BILI_FISH_DSH_BIN` |
| 3 | **DEEPSEEK_API_KEY** | 生成必失败（`MISSING_CREDENTIAL`） | 设环境变量，或在 DSH「模型」页保存一次 |
| 4 | **Python 3.10+** + `pip install -r requirements.txt` | OCR 与语音转写那两条腿废掉（探针退回保底） | 见下 |
| 5 | **ffmpeg** | OCR 抽帧不了 | 装 ffmpeg 并加进 PATH，或设 `BILI_FISH_FFMPEG` |
| 6 | **B 站凭证** `credentials.json` | 拿不到字幕、回复发不出去 | 手填（**秘密，永远不进仓库**） |
| 7 | **`config.json` 的 whitelist** | 首次运行会自动生成，但白名单为空 → **谁 @ 都不理** | 填你自己的 mid |

## 步骤

### 1. 拿到仓库

```powershell
git clone https://github.com/<你>/dsh-bili-fish.git
cd dsh-bili-fish
node bin/fish.mjs help      # 能打出帮助就说明 Node 这边通了
```

### 2. 装 Python 侧的依赖

```powershell
pip install -r requirements.txt
```

装完自测：

```powershell
python -c "from rapidocr_onnxruntime import RapidOCR; print('ocr ok')"
python -c "from faster_whisper import WhisperModel; print('asr ok')"
```

⚠️ **`av` 必须 `<14`**。`requirements.txt` 已经锁住了；如果手动装过别的版本导致转写报
`open() got an unexpected keyword argument 'metadata_errors'`，就 `pip install "av>=11,<14"`。

⚠️ 语音转写**首次运行会下载模型**（`small` 约 480MB），那时会卡一会儿，属正常。

### 3. 确认 dsh 能被找到

程序会 spawn `dsh --profile headless`，它按这几处依次找入口：

```
%BILI_FISH_DSH_BIN%                                    ← 你自己指定的
<node.exe 所在目录>\node_modules\@deepseek-ai\dsh\lib\bin.js
C:\Program Files\nodejs\node_modules\@deepseek-ai\dsh\lib\bin.js
%USERPROFILE%\AppData\Roaming\npm\node_modules\@deepseek-ai\dsh\lib\bin.js
```

都不在就设环境变量（把路径换成你自己的）：

```powershell
# 先找到它
npm root -g
# 假设输出 C:\Users\you\AppData\Roaming\npm\node_modules
setx BILI_FISH_DSH_BIN "C:\Users\you\AppData\Roaming\npm\node_modules\@deepseek-ai\dsh\lib\bin.js"
```

### 4. 配 API key

两种都行，任选其一：

- **环境变量**：`setx DEEPSEEK_API_KEY "sk-..."`（重开窗口生效）
- **DSH 凭据服务**：打开 DSH → 模型设置 → 保存一次 key

> 已知坑：某些 DSH 版本把 key 存在 `~/.dsh/.credentials.yaml` 的 `refs` 段，
> 而 headless 只读 `records` 段 → 会报 `MISSING_CREDENTIAL`。
> 本项目的 `lib/model.mjs` 会**兜底读 `refs.DEEPSEEK_API_KEY`** 并传给子进程，所以通常不用管；
> 但最稳的做法还是在「模型」页重新保存一次。

### 5. 填 B 站凭证

新建 `~/.dsh/bili-fish/credentials.json`（Windows：`C:\Users\<你>\.dsh\bili-fish\credentials.json`）：

```json
{
  "sessdata": "从浏览器 Cookie 里复制 SESSDATA",
  "bili_jct": "从浏览器 Cookie 里复制 bili_jct",
  "buvid3": "从浏览器 Cookie 里复制 buvid3"
}
```

- 只要**读**（字幕、素材）：`sessdata` 就够
- 要**发**评论：必须同时有 `bili_jct`（它是 csrf）

### 6. 配白名单

首次运行会自动生成 `config.json`，但 `whitelist` 是空的。填上你的 mid：

```json
{ "whitelist": ["你的mid", "鱼的mid"] }
```

也可以在网页控制台里改（`fish-web.cmd` → 配置 → 白名单）。

### 7. 生成桌面快捷方式（可选）

```powershell
node tools/make-shortcuts.mjs
```

会在桌面生成「bili-fish 常驻」「bili-fish 控制台」两个入口。
**换机器或移动目录后重跑一次**即可——桌面脚本里写的是绝对路径，不能跟着仓库走。

## 自检

```powershell
node bin/fish.mjs doctor
```

逐项检查 Node / Python / rapidocr / ffmpeg / dsh 路径 / API key / B 站凭证 / 白名单，
每项给 ✓ 或 ✗，并说明缺了会影响哪条腿。

## 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `模型调用失败：... MISSING_CREDENTIAL` | 没 key，或 key 只在不被读取的段 | 见步骤 4 |
| `找不到 dsh 入口（lib/bin.js）` | dsh 不在候选路径 | 设 `BILI_FISH_DSH_BIN` |
| 生成成功但正文为空 | 老版本把"报错"当成"空正文" | 已修；确认用的是最新代码 |
| OCR 一律失败 | 缺 ffmpeg 或 rapidocr | 见步骤 2、5 |
| `@` 了没反应 | whitelist 里没有你的 mid | 见步骤 6；看 `rejected.jsonl` 有没有 `not_whitelisted` |
| 字幕内容是歌词 | B 站 AI 字幕只转录了 BGM | 已内置 A+B 闸门，会自动落回 OCR；也可在 @ 里写「看画面」强制 |
