## 1. 定位

**一个可被召唤的工具，不是一条自主活鱼。**

- 用户（白名单成员）在 B 站视频评论区 **@ 它**，它把该视频读完，回一条**"有哪些观点 + 我怎么看"**的内容。
- 不做自主浏览、不做选片打分、不做日记、没有人设、没有沉默衰减。
- 存在形态：DSH 插件（MCP stdio），常驻宿主的 `setInterval` 循环。
- 账号：用户自己的小号（注册满 3 个月、有正常浏览记录）。

## 2. 通道与准入

### 2.1 只支持两个通道

| 通道 | 说明 |
|---|---|
| **视频评论区 @** | 从 `/x/msgfeed/at` 收件箱发现 |
| **楼中楼追问** | 同一个 `root` 下、`parent` 是鱼自己的 rpid |

**不支持私信**（已撤销）。**不支持图文/动态**（`business != 1` 一律静默忽略，记日志 `reason=unsupported_type`）。

### 2.2 白名单（硬闸，永不经过模型层）

```
whitelist: ["<mid1>", "<mid2>", ...]     # 配置项，必须显式包含自己
白名单为空 → fail-closed，鱼完全不响应
判定只看 mid，昵称只用于日志可读性
```

- 非白名单 → **完全静默**，只写日志 `reason=not_whitelisted`
- 白名单通过 → **一律当作"总结这个视频"处理**，不做意图分类（白名单只有自己，成本可接受）
- 准入通过后的失败 → **要回话**（见 §7.3）

### 2.3 视频锚点（不进模型层）

```
① 用 @ 所在评论区的 oid → view → bvid    ← 唯一来源
② 正文里贴的 BV / 链接一律忽略
③ 追问沿用首次召唤的那个 bvid
```

## 3. 素材获取：五级阶梯 + 探针分派

### 3.1 阶梯

```
L0  官方字幕         纯 token，零算力          ← 有就用（实测 75% 有，见 §3.0）
L1  ASR              token + 本地算力          ← 只服务剩下的 25%
L2  雪碧图探针        7.5MB + 0 token          ← 用来看"字在哪儿"
L3  1080P 抽帧 + OCR  下载 + 本地算力，0 token
L4  送图给模型        token ≈1500/图
```

### 3.0 实测：字幕覆盖率 75%（带登录态，24 条热门样本）

> 第 1 轮时我们假设"大部分视频没有字幕"。**实测推翻了它。**

| 项 | 数量 | 占比 |
|---|---|---|
| 有任何字幕 | 18 / 24 | **75%** |
| 其中人工字幕 | 0 | 0% |
| 其中 AI 字幕（`ai-zh`） | 18 | 75% |
| 完全无字幕 | 6 / 24 | 25% |

- **字幕全部是 B 站 AI 生成的 `ai-zh`**，没有人工字幕。部分视频还带 `ai-en/ai-ja/ai-es/...` 多语轨。
- 无字幕的 6 条集中在：音游 / GMV / 宅舞 / 影视剪辑 / 三农 / 搞笑 —— 也就是**没口播或口播极少的类目**。
- 按时长看没有明显规律（60s 以下 3/3 有，19 分钟那条反而没有）。

**这个数改变了默认路径**：字幕是主力（75%），ASR 只服务 25%，OCR 更少。
所以判定顺序必须是「**先看有没有字幕，没有才跑探针**」——有字幕还跑探针，等于白花 7.5MB 和几秒。

### 3.1.1 判定顺序（实现必须照这个来）

```
① 拉字幕轨 → 下载正文（auth_key 分钟级，拿到就下）
     └─ 成功 → L0，结束（连探针都不跑）
② 字幕为空 → 看竖屏？
     ├─ 竖屏 → L1 ASR（雪碧图对竖屏无效）
     └─ 横屏 → L2 探针 → 按字/帧分派 L1 / L3
③ 探针失败 → 保底 L3 OCR（设计定稿的降级规则）
```


### 3.2 探针决策表（**实测阈值**，不是估计）

探针 = 取 1-3 张雪碧图、跑 RapidOCR、数"平均每帧识别出多少字"。

| 字/帧 | 判定 | 走哪条腿 |
|---|---|---|
| **≥ 60** | 文字屏 / 文档 / 长图 | **OCR 主粮**（L3） |
| **5-60** | 硬字幕 / 大字标题 | **ASR 主粮**（L1），OCR 可选补 |
| **< 5** | 画面无字 | **ASR**（L1） |
| ASR 也空 且 OCR 无字 | — | 诚实降级 |

实测依据：

| 视频 | 字/帧 | 判定 |
|---|---|---|
| PPT 课件（2306s） | **195** | 文字屏 |
| 日常短视频（222s） | 11.9 | 有字幕 |
| 汽车长视频（3086s） | 11.0 | 有字幕 |
| 竖屏（557s） | 4.4 | 几乎无字 |

**两条硬规矩**：

1. 雪碧图 OCR **只能当探针**，绝不当正文（实测：字数准，字全错——"中共中央政治局委托" 被读成 "义受中央政治商委托"）。
2. **硬字幕不等于要 OCR**。5-60 这一档走 ASR，因为 ASR 1-2 分钟就够，OCR 要 5 分钟以上。

### 3.3 探针的自适应取样

```
取 1 帧（中段，避开封面）OCR
  ├─ ≥60 字 → 判文字屏，结束（约 2.2s）
  ├─ 5-60   → 再取 1 帧确认（换位置）
  └─ <5     → 再取 1 帧（换位置）；仍 <5 → 判无字（约 0.7s）
```
理由：实测同一视频 2 帧取到 0 字、3 帧取到 7.7 字——字幕不是每帧都有。

### 3.4 竖屏

`view.dimension.width < height` 或 `is_story=true` → **元数据直接判定，零请求**。
竖屏雪碧图有效宽度仅 118-124px/480（实测），**L2 探针对竖屏无效** → 竖屏直接按 L1 处理，ASR 空则如实说"读不了竖屏画面里的字"。

### 3.5 各腿的接口与坑

| 腿 | 接口 | 坑 |
|---|---|---|
| 字幕 | `/x/player/wbi/v2`（**必须 WBI 签名 + 登录**）→ `subtitle_url` | 旧 `/x/player/v2` 缺 `auth_key` → 403；`auth_key` 分钟级过期，URL 不能截断；**匿名必空，测不出真实覆盖率**（实测登录后 75% 有，全部是 `ai-zh`） |
| 雪碧图 | `/x/player/videoshot?index=1&aid=&cid=` | **匿名可用无需 Referer**；一次拿全片；`index[0]` 是哨兵；图号 `floor(k/100)`、行 `floor((k%100)/10)`、列 `k%10` |
| 弹幕 | `comment.bilibili.com/<cid>.xml` | **即使不发 `Accept-Encoding` 也返回 deflate**；要手动 `inflateRawSync→inflateSync→gunzipSync`；采样比不稳定（实测 90.7% 与 0.2% 都出现过），**不能拿条数当冷门证据** |
| 下载 | `/x/player/playurl?qn=80&fnval=1&platform=pc&high_quality=1` | 匿名只给 **720P**；登录才给 1080P（OCR 必须用登录态）；PCDN 节点会假死，需探活重试 |
| OCR 抽帧 | ffmpeg | **默认 5s/帧**（可配 3-10）；>60 分钟自适应放宽到 8s/帧 |

## 4. 指令词（代码层解析，不进模型）

| 词 | 作用 |
|---|---|
| `字幕` | 强制 L0/L1，不许看图 |
| `看图` | 强制上 L3/L4 |
| `详细` | 长度放宽到 800 字 |
| `简短` | 压到 150 字 |

- 正则全词匹配、大小写无关
- 多个出现按**最后一个**生效
- 都不出现 → 走 §3.2 自动判定
- 解析函数必须可单测

## 5. 生成

### 5.1 定标（纯代码，先算后写）

| 时长 | 正文字数 | 时间戳个数 |
|---|---|---|
| ≤ 3 min | 200-350 | 3 |
| 3-20 min | 300-500 | 4 |
| 20-60 min | 400-650 | 5 |
| > 60 min | 450-800 | 6 |

> 2026-11-04 改：原来是"字数 + 时间戳个数"，现在第三列是**观点条数**。

### 5.2 体裁（代码判）

- 知识 / 观点类 → 主张优先，只挑支撑主张的数据
- 杂谈 / 叙事类 → 观点可能藏在故事里，先提炼主张
- 音乐 / 情绪类 → 没有观点可提炼，两三句写感觉，不硬套"观点一二三"

### 5.3 时间戳 —— **第一版不要**

> 2026-11-04 用户明确要求：**输出不写时间戳**。
> 目标是"像把文字稿发给大模型问它有哪些观点"，不是"假装看过视频的观后感"。

- 正文里不出现 `MM:SS`
- 自检发现时间戳只记 warning，不算错
- 将来若恢复，规则是：行首纯文本、不许加粗/方括号、必须 ≤ duration、多 P 要加偏移

### 5.4 自检（代码执行，不合格重写一次）

**硬错 → 重写**

1. 长度 ≤ 1000（B 站硬限，超了命中 `12025`）；≤ `maxOutputChars`（900）
2. **总结 / 感悟 必须分开** —— 第二段为空 → 不通过
3. **总结段不许夹带评价** —— 第一段出现 我觉得/我更认同/站不住/漏洞 → 不通过
4. **感悟段必须有判断** —— 第二段没有上述表态 → 不通过
5. **假装看过**：出现 `我看了` / `画面` / `镜头` / `视频里能看到` / `亲眼` → 重写
   （我们只给模型文字稿，任何关于画面的声称都是编的）
6. 与标题最长公共子串 ≥12 字 → 判"复读"，重写
7. AI 腔词表命中 → 重写

**软提醒 → 只记录**

8. 偏短（< 目标下限 ×0.6）/ 偏长（> 目标上限 ×1.3）
9. 出现了时间戳（第一版不需要）
10. 总结段占比 <25% 或 >75%
11. `coverage` 低时在 prompt 里明确告知覆盖率，禁止夸大

### 5.6 输出结构（2026-11-04 用户核心要求）

> **"一定要把总结和感悟分开"** —— 这是硬结构，不是风格偏好。

```
第一段（总结）：只客观说这条视频在论证什么、有哪些主张，不评价
                ← 中间空一行
第二段（感悟）：我怎么看，赞同哪半、哪里站不住、有没有反例
```

`config.generate.separator = 'label'` 可改成「总结：」「看法：」带前缀的形态。

### 5.5 语气

无人设。像**认真读完一篇文字稿的人**在回答"这视频讲了什么观点、你怎么看"：
先点出它真正在论证什么，再给判断，不和稀泥、不复述标题、不寒暄。

## 6. 输出

### 6.1 挂楼层

```
新召唤：parent = 对方那条评论的 rpid，root = 该评论的 root（root=0 时用 parent 兜底）
追问：  parent = 追问那条 rpid，      root = 同一个 root
```
**必须在 parent 之下**，否则对方收不到"有人回复你"的通知。

### 6.2 拆分

- **默认不拆**；正文 > 700 字才拆；**最多 3 条**，每条 300-800 字
- 第 1 条：总评 + 前几章；第 2/3 条续
- 条间间隔 `10 + rand(0,10)` 秒
- 拆之前先 `GET /x/v2/reply/reply?root=` 确认前一条**真的发出去了**，没确认不发下一条

### 6.3 追问

- **永远追加一条新的**，绝不删原评论重发（B 站评论不能编辑，删了丢赞 + 重复通知）
- 追问靠 `--session-id` 复用同一个会话（见 §7.1），**不重发素材**，只把追问原话发过去
- 会话丢了 → 退化成"重发素材摘要 + 原总结 + 追问"，**不能因此失败**
- 只回答新增的那部分，不复述整条总结

### 6.4 进度消息

预计处理 >3 分钟时，先回一条"收到，正在看，约 N 分钟"。**这条不做删除**（删了留痕更奇怪）。

## 7. 运行时

### 7.1 模型调用

```bash
# prompt 走 stdin（不是 argv！）
cat prompt.txt | dsh --profile headless --json [--session-id <id>]
```

**三条实测结论**（2026-11-04 本机验证；`--session-id` 只在 `dsh headless --help` 里才看得到）：

| 能力 | 结论 |
|---|---|
| `task` 走 stdin | ✅ 支持（管道或 `-`）→ **彻底绕开多行 prompt 被 cmd.exe 截断的坑** |
| `--json` | ✅ newline-delimited 事件：`session` / `text` / `status(usage)` / `final` |
| `--session-id` | ✅ **存在，且真的复用上下文**（实测第二轮记得第一轮说的话） |

> ⚠️ **纠正**：本文早先写"headless 没有会话记忆"是**错的**——那是只看主 `--help` 得出的结论。
> 它的限制是：只能"采用**已存在**的会话"，不能自建；首次跑完要从 `type:"session"` 事件里把 id 收下来。

**因此对话策略是：每个 bvid 一个会话。**

- 首次处理某视频 → 新建会话，跑完记下 `sessionId`（存 `sessions.json`）
- 追问 → 带 `--session-id` → **上下文天然共享，不用重发素材**
- 不同视频互不污染
- 会话不存在（过期/清理）→ 自动脱掉 `--session-id` 重来一次，**不能变成永久失败**

### 7.2 上下文预算

因为会话可复用，**追问不必再塞素材**，额外开销只有历史累积。分配如下（总窗口 100k，可配）：

| 块 | 上限 | 何时带 |
|---|---|---|
| 系统指令 | ~1k | 每次 |
| 素材摘要（字幕/OCR/ASR + 时间轴） | **≤ 20k** | **仅首次**（追问靠会话记忆） |
| 本次追问原话 | ≤ 1k | 每次 |
| 输出预留 | ~4k | 每次 |

**仍然绝不把 5 万字 OCR 全文塞进去**——首次就该压到 20k 以内。

### 7.3 失败与回话

| 情况 | 回话？ |
|---|---|
| 非白名单 | ✗ 静默 |
| 图文/动态 | ✗ 静默 |
| 拿不到视频/字幕且 ASR 也空 | ✓ 回一句原因 |
| `-412/-352` 风控中 | ✗ **不回**（任何写都可能加重） |
| 失败回话额度 | **每天 ≤3 条**，同一楼只回一次失败 |

### 7.4 队列与并发

- **严格串行**，一次只处理一条
- 队列上限 **5**，超出丢弃 `reason=queue_full`
- **单条硬超时 15 分钟**：超时用已处理片段出结果，注明"只覆盖前 N 分钟"

### 7.5 熔断

`-412/-352/-799/-509/-10403` 或 HTTP 412/429 → 退避 **5 → 10 → 20 → 30 分钟**（封顶 30）；期间吃缓存，无缓存明确报错不硬闯。

### 7.6 素材缓存

- 按 `(bvid, cid, kind)` 缓存字幕/转写/雪碧图/pvdata，**7 天**
- **不缓存结论**——每次重新生成（追问需要新视角）

## 10. 里程碑

> **2026-11 调整**：实测字幕覆盖 75% 后，顺序变了 —— 先把"字幕 → 总结"这条主干打通（覆盖四分之三），
> ASR / OCR 只是给剩下 25% 补课的支线。原计划先做 ASR 是错的。

| 阶段 | 交付 | 覆盖 | 风险 |
|---|---|---|---|
| **M0** | `fish see <BV>` 盘点全部素材 + 判定（字幕优先） | — | 零（只读）✅ |
| **M1** | `fish summary <BV>`：字幕 → 定标 + 体裁 + prompt → 模型 → 自检 → 写文件 | **75%** | 零（只写本地）✅ |
| M2 | msgfeed 轮询 + 白名单准入 + 追问判定（只入库，不回复） | — | 零（只读） |
| M3 | 回复打通（自己 @ 自己 10 次） | — | 低 |
| M4 | ASR：无字幕 + 横屏口播类 → 转写（含"有没有口播"判定） | +15% | 零 |
| M5 | OCR：文字屏 → 1080P 抽帧 + 行级去重（输出与字幕同构） | +10% | 零 |
| M6 | 串行 worker + 熔断 + 拆分楼层 + 进度消息 | — | 中 |

## 11. 三种素材必须同构

字幕 / ASR / OCR 三种来源，最终都产出同一种格式：

```
[00:37] 文本行…
[00:42] 文本行…
```

下游 composer 只认这一种格式，不关心来源。**这是整个实现能简化的关键。**

OCR 的行级去重规则：相邻帧的行做前缀匹配，滚动时新旧行重叠部分丢弃；按时间排序。

| 项 | 原因 |

| 举报 / 点赞 / 投币 | 只做总结，不做互动 |

## 13. 红线
